# nodejs-hw — 03-validation

Express + Mongoose API заметок. Ветка задания: `03-validation`.

## Запуск

```bash
npm install
npm run dev
```

В локальном `.env` нужны `PORT=3000` и `MONGO_URL` со строкой существующей базы MongoDB Atlas. Не публикуйте `.env`. Импортированные ранее заметки остаются в коллекции `notes` той же базы; повторно импортировать их не нужно.

## API

| Метод  | Путь             | Результат                            |
| ------ | ---------------- | ------------------------------------ |
| GET    | `/notes`         | Список с пагинацией и фильтрами, 200 |
| GET    | `/notes/:noteId` | Заметка, 200                         |
| POST   | `/notes`         | Созданная заметка, 201               |
| PATCH  | `/notes/:noteId` | Обновлённая заметка, 200             |
| DELETE | `/notes/:noteId` | Удалённая заметка, 200               |

Пример: `/notes?page=1&perPage=5&tag=Todo&search=hello`.

Параметры: `page` — целое от 1, по умолчанию 1; `perPage` — целое от 5 до 20, по умолчанию 10; `tag` — необязательный тег из `TAGS`; `search` — необязательная строка, допускается пустая. Поиск через `$regex` без учёта регистра по `title` и `content`. Фильтры работают совместно, количество страниц считается по отфильтрованным заметкам.

Ответ GET `/notes`:

```json
{
  "page": 1,
  "perPage": 10,
  "totalNotes": 40,
  "totalPages": 4,
  "notes": []
}
```

Числа в примере условные. `notes` содержит документы текущей страницы. Если совпадений нет, `totalNotes` и `totalPages` равны 0, а `notes` — пустой массив.

POST принимает обязательный непустой `title`, необязательные `content` (допускается пустая строка) и `tag`. PATCH принимает хотя бы одно из этих трёх полей. Параметр `noteId` проверяется через Mongoose `isValidObjectId` для GET/PATCH/DELETE. Схемы находятся в `src/validations/notesValidation.js`; middleware `celebrate(schema)` подключены в маршрутах, `errors()` — в `src/server.js` перед глобальным обработчиком ошибок.

Неверные данные — 400; отсутствующая заметка — 404 с `Note not found`; неизвестный маршрут — 404 с `Route not found`. Другие ошибки обрабатываются глобальным middleware. Подключение к MongoDB выполняется до запуска сервера; при отказе процесс завершается с кодом 1.

## Проверки

```bash
npm run lint
npm run format:check
```

При подготовке прошли 44 HTTP-проверки реальных маршрутов Express и celebrate: пагинация, совместные фильтры, значения по умолчанию, пустые результаты, корректные/некорректные ID и тела запросов, CRUD-статусы и 404. Обращения к базе в этих проверках заменены тестовыми ответами; это не проверка подключения к вашему Atlas или деплоя Render.
