# nodejs-hw — 02-mongodb

Второе задание: Express + MongoDB через Mongoose. Основа взята из вашей ветки `01-express`. Код второго задания должен находиться в новой ветке **02-mongodb** того же репозитория.

## 1. Создать ветку и перенести файлы

В терминале вашего существующего локального репозитория nodejs-hw:

```bash
git switch 01-express
git pull origin 01-express
git switch -c 02-mongodb
```

Затем скопируйте содержимое папки nodejs-hw из архива в свой репозиторий с заменой файлов. Сохраните существующую папку .git и свой .env. Не создавайте новый репозиторий и не удаляйте main/01-express.

Если ветка 02-mongodb уже есть, используйте `git switch 02-mongodb` вместо команды создания ветки.

Выполните:

```bash
npm install
```

## 2. Настроить MongoDB Atlas

Без собственной базы этот сервер не запустится. MONGO_URL — строка подключения MongoDB, а не адрес Render и не токен из заданий React.

1. Откройте https://cloud.mongodb.com и войдите/зарегистрируйтесь.
2. Создайте проект и кластер; для учебной работы выберите бесплатный вариант, если он доступен в вашем интерфейсе.
3. Создайте Database User с именем и паролем для подключения к базе. Это отдельный пользователь базы, не логин вашего аккаунта Atlas.
4. В разделе Network Access / IP Access List добавьте `0.0.0.0/0`, как требуется в задании, и подтвердите запись.
5. У кластера выберите Connect → Drivers → Node.js и скопируйте предоставленную строку подключения.
6. Подставьте пароль пользователя базы вместо `<db_password>` и укажите имя базы **notehub** после `.mongodb.net/`, перед `?`.

Пример структуры (это шаблон, а не рабочие учетные данные):

```dotenv
MONGO_URL=mongodb+srv://USERNAME:PASSWORD@YOUR-CLUSTER.mongodb.net/notehub?retryWrites=true&w=majority
```

Используйте настоящий hostname из Atlas. Если пароль содержит специальные символы, их нужно кодировать для URI. Саму строку с паролем храните в .env и настройках Render; .gitignore исключает .env из Git.

## 3. Заполнить .env и запустить

В существующий .env рядом с package.json добавьте MONGO_URL. Если .env еще нет, создайте его по образцу .env.example:

```dotenv
PORT=3000
MONGO_URL=ваша_полная_строка_подключения_из_Atlas
```

Не меняйте имена **PORT** и **MONGO_URL**.

```bash
npm run dev
```

При успешном подключении появится:

```text
✅ MongoDB connection established successfully
Server is running on port 3000
```

Сервер начинает слушать порт только после подключения базы. При отсутствии MONGO_URL или ошибке подключения запуск завершается с ошибкой. Без PORT используется 3000.

Откройте http://localhost:3000/notes. Пока коллекция пуста, ответ `[]` нормален.

## 4. Импортировать notes.json из задания

Скачайте **исходный notes.json по ссылке в LMS**. На скриншоте адрес этой ссылки не виден, поэтому официальный набор данных не включен в архив и не заменен выдуманными заметками.

Для импорта через MongoDB Compass:

1. Подключитесь к Atlas с той же строкой подключения.
2. Создайте/откройте базу **notehub** — она должна совпадать с именем базы в MONGO_URL.
3. Создайте/откройте коллекцию **notes**. Модель явно использует это имя коллекции.
4. Выберите Add Data → Import JSON or CSV file, укажите notes.json и выполните импорт.
5. Обновите http://localhost:3000/notes — должны появиться импортированные документы.

Если в вашей версии Atlas есть импорт JSON через интерфейс просмотра коллекции, его тоже можно использовать. Не импортируйте данные повторно в ту же коллекцию без проверки: это может создать дубликаты или ошибки одинаковых _id.

## 5. Проверить API

Ответы возвращают сами документы или массив, без оболочек status/data/message для успешных CRUD-запросов.

| Запрос                                             | Статус | Результат                       |
| -------------------------------------------------- | ------ | ------------------------------- |
| GET /notes                                         | 200    | Массив всех заметок             |
| GET /notes/:noteId                                 | 200    | Найденная заметка               |
| POST /notes                                        | 201    | Созданная заметка               |
| PATCH /notes/:noteId                               | 200    | Обновленная заметка             |
| DELETE /notes/:noteId                              | 200    | Удаленная заметка               |
| GET/PATCH/DELETE с корректным, но отсутствующим ID | 404    | `{"message":"Note not found"}`  |
| Неизвестный URL, включая /test-error               | 404    | `{"message":"Route not found"}` |

Для POST/PATCH используйте Postman, Insomnia или другой HTTP-клиент. Укажите Content-Type: application/json.

Пример POST http://localhost:3000/notes:

```json
{
  "title": "First MongoDB note",
  "content": "Testing the new API",
  "tag": "Work"
}
```

Скопируйте `_id` из ответа и подставьте вместо :noteId в GET/PATCH/DELETE.

Пример тела PATCH:

```json
{
  "title": "Updated note",
  "tag": "Important"
}
```

Модель: title обязателен и обрезает пробелы по краям; content необязателен, по умолчанию пустая строка, тоже trim; tag по умолчанию Todo. Допустимы ровно Work, Personal, Meeting, Shopping, Ideas, Travel, Finance, Health, Important, Todo. createdAt/updatedAt создаются автоматически через timestamps: true.

PATCH изменяет только title/content/tag, возвращает новое состояние и проверяет правила модели. Пропущенные поля сохраняются. Отсутствующий документ не создается автоматически.

Ошибки модели возвращают 400 через http-errors; несуществующая заметка — 404; остальные ошибки — 500 либо статус, который уже есть у ошибки. Формат всегда `{"message":"..."}`. Отдельная проверка формата MongoDB ID не добавлена: по условиям на этом этапе предполагается корректный ID.

## 6. Проверки кода

```bash
npm run lint
npm run format:check
```

Для запуска без nodemon:

```bash
npm start
```

Сервер разделен на controllers, db, middleware, models и routes. В server.js роутер подключен через app.use(notesRoutes), без переноса /notes в точку подключения. Обработчик 404 стоит после роутов, errorHandler — последним. Старый /test-error удален. pino-http и pino-pretty сохранены в dependencies.

Проверки ESLint и форматирования выполнены. Также прошли 32 проверки модели, контроллеров и регистрации маршрутов; обращения контроллеров к базе в этих проверках заменены тестовыми ответами. Полная проверка HTTP-запросов с реальной MongoDB в этой среде не завершена: локальный процесс MongoDB останавливается из-за ограничений среды. После подключения своего Atlas проверьте все пять CRUD-операций перед сдачей.

## 8. Деплой на Render

Можно создать новый Web Service для второго задания, чтобы сохранить работающий деплой первого. Либо переключить существующий сервис на ветку 02-mongodb, если отдельный старый деплой больше не нужен.

Настройки сервиса:

| Поле              | Значение                               |
| ----------------- | -------------------------------------- |
| Repository        | PlatonKhuzin/nodejs-hw                 |
| Branch            | 02-mongodb                             |
| Language          | Node                                   |
| Root Directory    | Пусто, если package.json лежит в корне |
| Build Command     | npm ci                                 |
| Start Command     | npm start                              |
| Health Check Path | /notes                                 |

В Environment Variables обязательно добавьте:

```dotenv
PORT=10000
MONGO_URL=ваша_настоящая_строка_подключения_к_Atlas
```

В MONGO_URL должно быть то же имя базы, куда импортирован notes.json. Не оставляйте в значении `<db_password>` и другие шаблонные части.

Запустите Deploy и проверьте сообщение об успешном подключении MongoDB в логах. Откройте публичный адрес сервиса с /notes и проверьте все пять CRUD-операций. На корневом адресе / без /notes будет 404 — HTML-страницы здесь нет.

В вашем аккаунте кластер и деплой автоматически не создавались. Их нужно настроить перед сдачей.

После последнего push подождите 5 минут, затем отправьте две ссылки: на GitHub-ветку 02-mongodb и публичный URL сервиса Render.
